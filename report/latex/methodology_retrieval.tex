\subsection{Chunking, indexing and retrieval}
\label{subsec:chunking_retrieval}

Chunking divides extracted content into searchable units. In financial reports, splitting a table between its row label and year column can preserve a number while losing its meaning. FinTrace therefore follows document structure rather than applying a fixed word count to every page~\cite{fintraceRetrieval2026}.

The chunk builder retains headings, text boundaries and table relationships. Table rows carry the relevant column headers and source context. Oversized prose blocks are split at sentence or word boundaries. Smaller child chunks support precise matching, while parent records retain the surrounding context. The configured limits are 2,400 UTF-8 bytes per child and 10,000 per parent, with at most three table rows in a child. These limits measure bytes rather than model tokens. Nearby footnotes are retained as possible context, but proximity does not prove which values they qualify. Ambiguous table evidence is excluded from calculations pending review.

Each unit records the bank, report, reporting year, PDF page, source blocks or rows and parent record. Units, financial basis, business scope and publication version are included where resolved. This metadata supports filtering and page references even when the PDF and printed page numbers differ. Context is added to short rows only when it can be established from the source.

Structured evidence uses two retrieval methods. BM25 ranks passages by informative shared terms. Dense retrieval uses Qwen3-Embedding-0.6B to represent text as numerical vectors, allowing related wording to be matched~\cite{qwenEmbedding}. Reciprocal rank fusion combines the two ranked result lists. Vectors are stored locally as NumPy arrays and searched by exact similarity. Tokenizer checks constrain the model input, while the evidence supplied for an answer has a separate size limit. Appendix~\ref{app:runtime_details} records these settings.

Prose from the full 1,021 pages follows a different process: keyword ranking uses contextual and phrase signals, then the local model selects passages. It is not a dense index of every report. This extends access to explanations without approving every table for numerical use.

Numerical lookup considers indexed financial rows matching the requested bank and measure, rather than only the first five hybrid search results. Binding, meaning matching the requested figure to its source cell, then checks the row, digits, period, unit, financial basis, business scope, publication version and conflicting values. Housing lending cannot be substituted with total loans, or net interest income with net interest margin. Explicit details in the question take precedence over optional interface filters~\cite{fintraceRuntime2026}.

Fixed size splitting and additional reranking were considered during development. Choices were informed by observed failures rather than assumed complexity. The tests used to guide these changes are development evidence, not an unbiased estimate of current accuracy. Relevant retrieval, correct cell matching and complete answers remain separate outcomes.
