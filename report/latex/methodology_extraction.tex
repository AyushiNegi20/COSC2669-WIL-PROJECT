\subsection{PDF extraction and evidence preservation}
\label{subsec:pdf_extraction}

Extraction was designed to preserve the relationship between each figure and its row label, reporting period, unit and financial basis. Each PDF is recorded with its issuer URL, document identifier and SHA-256 checksum. The checksum acts as a file fingerprint, allowing a changed source to be detected and an answer to be traced to the version used.

The process has two layers. pypdf extracts native text from all 1,021 pages. Docling identifies table structure on 72 selected financial pages containing results, reconciliations, balances and supporting notes~\cite{doclingSoftware}. Because these pages contain selectable text, optical character recognition (OCR), which reads text from images, is disabled. Docling runs locally on CPU with four threads. Cached conversions are reused only when the source, pipeline and library versions match. Selecting 72 pages kept detailed table processing manageable; it was a project boundary rather than a technical requirement~\cite{fintraceExtraction2026}.

Four libraries were compared in six configurations on an 18-page development sample. Checks examined whether values retained their correct row relationships and order, rather than merely appearing in the extracted text. Docling's representation and performance on this sample supported its selection. However, the lighter table strategies were untuned and the sample informed subsequent fixes. The comparison therefore does not establish a universal ranking or performance on an untouched extraction test set~\cite{fintraceExtraction2026}.

Raw converter output is retained separately from cleaned evidence. Records preserve cells, merged cell spans, headings, page references, coordinates and correction logs. In some CBA tables, invisible trailing brackets appeared in extracted text. A targeted pdfplumber check inspects source characters and colours before removing such brackets, while preserving visible brackets that indicate negative values. Unresolved cases remain flagged.

An additional audit checks simple numerical values in every stored table cell against page text and source characters at the recorded coordinates. Mixed text and unresolved cases enter a review queue. Agreement can reveal character extraction errors, but cannot by itself confirm the year, unit or financial meaning assigned to a value~\cite{fintraceExtractionFreeze2026}.

The resulting evidence supports broader prose search and separately checked calculations. Tables not yet validated and content available only in charts remain limitations. Evaluation answer keys are not passed into the document evidence.
